## [2.55.1] - 2026-05-20

### Added
- Added an option to toggle `ResumePolicy` on/off while editing the policy

### Changed
- Core database connection pools now open connections on demand instead of pre-allocating the full pool at startup, reducing idle Postgres connection usage and avoiding `max_connections` saturation in larger deployments.
- Re-queuing the same content deletion no longer creates duplicate pending work or inflates the pending-delete lag metric.
- When a `NO_SUBSCRIBERS` error occurs due to "no topics matched the publish rules" (formerly 'criteria'), use a new error cause: "No publish rules were satisfied" to help distinguish from other `NO_SUBSCRIBERS` issues
- Moved JSON schema generation to deltafi-common

### Fixed
- Fixed issue with long json strings not wrapping in the context viewer 
- Fixed an error preventing `ResumePolicy` changes from saving
- On multi-node local object storage deployments, a fast-delete worker on one node could clear another node's pending deletion before that node had processed it, leaving the local file behind. Each worker now only clears its own pending work.
- Fast delete issue with "Argument list too long" errors
- TUI: `deltafi properties set` was not idempotent and generated errors on non-delta sets
- Reduced `RateLimitService` startup log noise — previously dumped the full `JedisPool.toString()` (including an embedded Java stack trace) as the log message; now logs just the configured pool size.
- Reduced plugin registration log noise — the full `PluginRegistration` payload (action descriptors, flow plans, lookup tables, etc.) is no longer logged on every successful registration. It is now logged only when registration fails, where it's useful for diagnosis.
- TUI: get properties NPE when getting unset system properties with default values
- Fixed an issue where the `deltafi-valkey` startup logs were not captured by vector 

### Deprecated
- Deprecated org.deltafi.actionkit.action.parameters.annotation.Size annotation

### Tech-Debt/Refactor
- Refactored the deltafi-action-kit ActionRunner removing all dependencies on spring from the service
- Refactored the deltafi-action-kit `HeartbeatService` removing all dependencies on spring from the service
- Fix test suite startup race condition 

### Upgrade and Migration
- Upgrade Java base image to deltafi/deltafi-java-jre:21.0.11-alpine-0
