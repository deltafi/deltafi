## [2.55.0] - 2026-05-12

### Added
- New egress action `ActiveMQPublish` supports publishing content to a JMS destination
- `deltafi artifacts list` now supports a `--show-type` flag that adds a Content-Type column to the output.
- New system property `autoResumeEnabled` (group: error controls, default: `true`). When set to `false`:
  - The scheduled auto-resume task skips all work regardless of individual rule state.
  - New errors are no longer matched against resume policies, so newly errored DeltaFiles are not stamped with a `nextAutoResume` (matches the behavior of disabling every individual policy).
  - DeltaFiles already carrying a `nextAutoResume` timestamp keep it; they are simply not acted on by the scheduler while the global toggle is off. When the toggle flips back to `true`, the scheduler picks them up on its next pass.
- Web Terminal added for compose orchestrated systems.  To enable web terminal, the following needs to be added to site/values.yaml:
```yaml
deltafi:
  webTerminal:
    enable: true
```
- Added an option to disable `ResumePolicies`. Disabling a policy prevents existing DeltaFiles from resuming based on that policy and newly errored DeltaFiles will not apply the policy. When the policy is enabled any previously scheduled resumes for the policy will fire if the DeltaFile is still eligible for resume.

### Changed
- Documentation generator for actions now includes the action type (full class path) in the markdown document
- Deleting a `ResumePolicy` now clears out the next auto resume fields for any DeltaFiles that were scheduled to be resumed based on the policy that was deleted

### Fixed
- Fixed a bug in the Decompress action that fails to decompress a GZ file which has a ZIP file inside when auto-detecting format
- Fixed the graphql URL in the GraphQL API documentation
- Fixed the sample request body in the `POST /api/v2/content` documentation
- `deltafi artifacts publish --content-type <mime>` now stores the specified MIME type on the published version. Previously the flag was silently ignored and every uploaded artifact was recorded as `application/octet-stream` regardless of the value passed.
- Fixed ordering by the data source name in the `deltaFiles` query

### Tech-Debt/Refactor
- Minor fixes to TUI from `go fix`
- Refactored the java PluginRegistrar so it does not require external dependencies (spring/feign)

### Upgrade and Migration
- Database migration v77 does the following
  - adds a new column to track the enabled flag on resume rules (fast migration)
  - add a new field to delta_file_flows to track the next_auto_resume_reason and indexes the field (this is a quick change on systems where there are not many errored flows waiting for auto-resume)
